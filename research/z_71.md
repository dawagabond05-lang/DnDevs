## 1. Options

1. Create the project and push the repo. Outward: needs a fresh OK.
2. Add `ANTHROPIC_API_KEY` as a masked CI variable. Bedrock or Vertex through OIDC also works.
3. Give the job a GitLab credential. On Free: `CI_JOB_TOKEN` with "Allow Git push requests" turned on (off by default; S10). A project access token needs Premium on GitLab.com (S7).
4. Add the `claude -p` job to `.gitlab-ci.yml`, triggered by `web` or MR events.
- Free tier: 400 compute minutes a month (S14).
- UNKNOWN: whether a runner on Dawa's own machine is exempt from the minutes; whether the job token alone can open MRs.

**B. Duo "Claude Code Agent by GitLab"** (S2, S4). VERIFIED.
- Needs Premium or Ultimate, Duo turned on, and GitLab Credits. The docs also say "enabled for verified customers, contact support".
1. In the AI Catalog, select Enable, the project and a trigger (mention or reviewer).
2. GitLab creates the service account `ai-<agent>-<group>` with the Developer role.
- You cannot create custom external agents on GitLab.com.
- Branch names come from the prompt only: `feature/<…>` in S3, `^duo/…` in S2. INFERENCE: `ADDITIONAL_INSTRUCTIONS` cannot enforce `young-sage/`.
- The job runs with `--setting-sources ''` (S3). INFERENCE: skills and CLAUDE.md are ignored.
- MRs are attributed to the human who triggered the agent (S5), and authors cannot approve by default (S8). INFERENCE: Dawa could not approve.
- Changed recently: trigger types (19.0-19.4).

**C. Claude Code on the web.** Clone and PR need GitHub. A GitLab repo only goes up as a bundle (`CCR_FORCE_BUNDLE=1`), with no push back (S12). VERIFIED. Not viable.

**D. Forge intake.** From v2.1.233, `claude --worktree <MR URL>` fetches `merge-requests/N/head` (S13, Aug 2026). An MR `.patch` URL also works with `git am` (S11). VERIFIED.
